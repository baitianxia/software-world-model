# 产品愿景与边界

Software World Model 面向需要持续理解软件系统的人和 Agent。软件世界模型是软件系统在精确版本和上下文上的持久、可验证、可更新外部认知：它独立于任何模型会话或隐藏状态，表达实体、关系、行为、约束、状态、来源、覆盖范围、冲突和未知，使 AI 不依赖单次会话记忆就能获得稳定的系统认知基础。工程手册、结构地图、摘要和检索提示只是这份认知面向人或任务的投影，不是世界模型本身。

这一核心概念从产品起点至今没有改变。本轮改变的是默认问答如何使用世界模型：来源观察经独立准入和原子发布成为正式认知；严格世界模型任务只从固定 Snapshot 复用它；默认工程问答则从这份认知出发，由独立 Investigation LLM 自适应调查同一 exact revision，平台受控取证，调查结束后封包、回答并独立复核。

## 产品承诺

- 软件结论可追溯到被授权的精确来源和上下文。
- 已发布知识可跨任务复用，而不依赖某次模型会话记忆。
- 不充分、冲突、未知和运行结果未知都被显式披露。
- 模型可以规划、提议和审核，但不能自行获得来源权限或写入正式知识。
- 默认工程问答先服务用户的工程目标与期望抽象层级，代码是按需核实和丰富答案的证据，不是默认正文模板。
- 世界模型提供系统认知而不是题型答案模板；模型可以基于调查发现动态决定下一步，但每项来源操作仍由平台重新授权并审计。
- 系统辅助答案在同等资源约束下不得低于直接调查软件来源的基线。
- 对不同工程、语言、框架和问题类型使用同一套证据流程；扩展来源能力不能通过在问答层增加题型补丁实现。

## 非目标

- 不把原始仓库、日志或模型输出直接称为正式知识。
- 不构建通用自治 Agent 平台、无限工作流引擎或隐藏的来源访问旁路。
- 不在系统规范中冻结某一迭代的模型、Provider、数据集或发布时间。
- 不因评测通过自动执行生产启用。
- 不承诺每个问题都有肯定答案；超出已授权来源、文本能力或固定版本边界的问题必须如实披露证据缺口。
- 不把 `ENGINEERING_QA` 的受控源读取伪装成 `WORLD_MODEL` 命中，也不在知识缺口后静默切换回答模式。
