# 产品愿景与边界

Software World Model 面向需要持续理解软件系统的人和 Agent。软件世界模型是软件系统在精确版本和上下文上的持久、可验证、可更新外部认知：它独立于任何模型会话或隐藏状态，表达实体、关系、行为、约束、状态、来源、覆盖范围、冲突和未知，使 AI 不依赖单次会话记忆就能获得稳定的系统认知基础。工程手册、结构地图、摘要和检索提示只是这份认知面向人或任务的投影，不是世界模型本身。

这一核心概念从产品起点至今没有改变。本轮改变的是默认产品如何使用世界模型：来源观察经独立准入和原子发布成为正式认知；严格世界
模型任务只从固定 Snapshot 复用它；默认工程 Chat 则由一个主工程 Agent 以这份认知为起点，在平台受控的工具、证据与独立审核边界内
持续理解对话、形成假设和计划、观察结果、重规划并回答。世界模型和主工程 Agent 是两项互补的核心能力，任何一方都不能被另一方替代。

## 产品承诺

- 软件结论可追溯到被授权的精确来源和上下文。
- 已发布知识可跨任务复用，而不依赖某次模型会话记忆。
- 不充分、冲突、未知和运行结果未知都被显式披露。
- 主工程 Agent 可以维护目标、假设、计划、子任务、观察和完成判断，但不能自行获得来源权限、业务权威或正式知识写入权。
- 默认工程 Chat 先服务用户持续的工程目标与期望抽象层级，代码是按需核实和丰富答案的手段，不是默认正文模板。
- 世界模型提供系统认知而不是题型答案模板；主 Agent 可以基于新发现动态修改调查和回答方向，但每项来源操作仍由平台重新授权并审计。
- Chat 必须理解追问、指代、纠正、深入和总结；对话工作状态、软件世界模型和当前回答证据保持不同身份。
- 系统必须证明额外复杂度产生真实产品价值：相同 Agent 下世界模型认知+源码不得弱于仅源码，必须有非 locator 认知贡献；完整系统逐题
  不得弱于直接相关证据、仅源码 Agent 和实际 current Codex，并在独立盲评中总体严格超过 current Codex。成本、时延或调用数不能补偿
  答案质量平局或退步。
- 对不同工程、语言、框架和问题类型使用同一套证据流程；扩展来源能力不能通过在问答层增加题型补丁实现。

## 非目标

- 不把原始仓库、日志或模型输出直接称为正式知识。
- 不构建拥有任意 shell、写入、网络或隐藏来源旁路的无边界自治 Agent 平台，也不把本产品扩张成通用工作流引擎。
- 不在系统规范中冻结某一迭代的模型、Provider、数据集或发布时间。
- 不因评测通过自动执行生产启用。
- 不承诺每个问题都有肯定答案；超出已授权来源、文本能力或固定版本边界的问题必须如实披露证据缺口。
- 不把工程 Chat 的受控源读取伪装成 `WORLD_MODEL` 命中，也不在知识缺口后静默切换回答模式。
