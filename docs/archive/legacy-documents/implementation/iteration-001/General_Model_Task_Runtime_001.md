## 已实现能力

系统现已具备一条可恢复的通用任务链路：

1. 把用户原始问题拆成一个或多个必须回答的问题，并由另一独立职责复核是否遗漏或篡改原意。
2. 只在明确授权、来源和版本边界均已冻结时，提出有界的来源调查动作；平台重新校验并执行动作，模型不能直接访问文件、命令行、网络或其他工具。
3. 从平台提供的精确材料提出正式事实，再由另一独立职责复核；平台最终重建引用、行范围和正式知识对象。
4. 对每个问题只读取一个精确知识版本，判断证据是否充分；模型返回的任何引用都必须属于本次精确读取集合。
5. 如果初次判断存在知识缺口且用户已经授权调查，系统执行一次受控知识更新，发布新知识版本后重新检查全部问题。调查失败、没有完整覆盖或没有发布新版本时停止，不用源码直答补洞。
6. 答案只能选择已经由充分性证明授权的正式知识，正文由平台从正式命题重建；同一事实支持多个问题时正文只展示一次并合并证明引用，知识缺口、冲突和未知必须保留。
7. 独立答案复核通过后才签发响应授权。当前本地接口只返回“已授权、尚未执行外部发送”的结果，不伪造可靠交付状态。

候选证据检索遵循“任一提示词命中即可进入候选集”。提示词只负责避免漏掉可能相关的正式知识，不代表证据已经充分；是否真正支持整个问题仍由独立充分性复核决定。需求计划、来源调查建议、事实候选、事实复核或回答草稿若结构不合法、字段互相矛盾、夹带保留字段标签或遗漏问题，会在各职责的有界次数内重新生成且每次都有独立调用记录；事实候选最多10条，并为连续截断后出现的精确契约错误保留最多五次修正机会。版本比较任务必须完整读取父版本和目标版本的每个必需路径后才能停止。停止调查时完全等于已授权父版本或目标版本的未使用字段回显会被忽略；陌生版本、路径或其他可执行参数仍立即拒绝。任何越权来源动作或不属于当前问题授权范围的证据引用都不会通过重试放宽边界。

## 恢复与一致性

- 同一逻辑模型调用完成后，重试会恢复原始输出，不再次向模型服务发出请求。
- 模型请求结果未知时，同一逻辑调用保持未知，不通过更换请求标识暗中重发。
- 同一任务重试会恢复原需求、知识判断、答案草稿、复核和授权；不得更换知识版本、需求计划或答案正文。
- 模型方案被停用、替换或评估资格失效后，已有服务实例也会在下一次执行前重新检查并停止。
- 六个模型职责共享一个由全部提示词、输出结构和职责边界计算出的实现指纹。运行组件的实现指纹和评估证明必须与当前启用记录完全一致，防止“评估一版、运行另一版”。
- 需求生成与需求复核、事实生成与事实复核使用不同职责标识和不同模型调用记录；答案生成与答案复核也保持分离。
- 产品未见项目验收记录采用只追加存储，绑定精确能力评估证明、六职责实现指纹、任务集、两侧答案和独立比较结果。评审来源必须同时区别于直接回答来源和本系统回答来源；本系统正确性或完成度低于直接回答、存在重大错误、记录过期或被篡改时均不能启用。
- 能力评估必须覆盖需求保真、来源调查、事实依据、证据充分性、答案来源闭合和答案语义复核六类职责；每类结果绑定预先封存的参考答案并由不同来源独立复核。结果未知时不自动重发，明确的契约失败也不能在重试时再次执行。
- 旧能力评估不能只凭相同方案名称复用。启动门禁会同时核对实现指纹、接口符合性结果、配置指纹、实际模型身份和适配器版本，任一变化都会使旧资格失效。

## 本地浏览器与接口

服务根路径提供无需登录的浏览器聊天页面。用户只需输入本地Git项目绝对路径、分析版本和可选读取范围；页面会隐藏作用域、来源绑定、固定提交、知识快照和调查预算等技术字段。最近六条对话可用于理解后续问题中的指代，但历史回答不会被当作源码事实，最终结论仍必须来自当前固定版本的正式知识。

`POST /v1/tasks/prepare-answer` 接收精确知识版本和自然语言问题。调用方可选填 `investigation`，其中必须明确来源、绑定、目标类型、目标参数和资源上限。接口返回：

- 逐问题知识判断；
- 受正式知识约束的答案正文和逐项声明；
- 复核结果；
- 响应授权；
- `delivery.performed=false`，明确表示尚未执行外部聊天通道交付。

默认启动方式未装配已评估并启用的通用模型方案，因此该接口安全关闭并返回“真实集成尚未开放”。

正式装配入口会同时重读当前模型接口符合性结果、通用能力评估证明、独立产品验收记录和显式启用决定，并核对模型、适配器、配置指纹、六职责实现指纹、资料等级和评估证明引用。只有全部一致且两类证明都在有效期内时，服务才可使用以下显式参数启动；缺少任一参数、任一证明过期或验收记录无法校验，都会在监听端口前停止：

```bash
PYTHONPATH=src python3 -m software_world_model.interface.http_api \
  --database ./swm.sqlite3 \
  --host 127.0.0.1 \
  --port 8080 \
  --enable-activated-model \
  --conformance-result ./var/conformance/<current-result>.json \
  --activation-environment <exact-environment>
```

该命令不会把“环境变量中存在密钥”解释为启用。普通启动不带 `--enable-activated-model` 时仍是离线模式。

## 当前结论和剩余限制

288项离线测试证明状态、边界、恢复和失败关闭机制按当前实现工作；六类通用能力评估与两个陌生工程六题产品验收均已通过，并绑定同一实现指纹、模型接口结果和配置。本机浏览器页面和真实回答闭环也已验证，系统达到本轮“可人工体验”标准。

仍需保持以下边界：

1. 能力证明和产品验收记录均有有效期；过期或实现、模型、接口配置变化后必须重验。
2. 生产启用尚未执行，不能把“验收通过”描述成“已上线”或“已对外提供服务”。
3. 当前HTTP服务只允许本机访问且没有认证；本机人工体验不需要登录。在设计并验收外部访问边界前，不应通过代理、端口转发或修改监听限制把它暴露到其他设备。
4. `local-browser`只授权本机人工体验；历史专项评估不能替代当前两类证明，也不能把该记录解释成生产启用。
