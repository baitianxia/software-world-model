## 6. Coverage Contracts

Coverage 是可验证 State/Argument/Assessment依赖，不是正式知识成员。

本文新增自校验对象统一使用唯一三段式：`XCore`保存完整closed preimage且明确排除`XDigest`、`XEnvelope`以及依赖二者的后置对象；`XDigest=DIGEST(XCore)`；`XEnvelope=TUPLE(ENUM(exactEnvelopeTag),XCore,XDigest)`。Verifier必须先按closed codec解码Core，再从其canonical bytes独立重算Digest，最后校验Envelope tag、Core和Digest；把自身Digest或Envelope塞回Core、对调用方map/opaque bytes取摘要、或只保存Digest而没有可解析Core均失败关闭。下文名称以`Ref|Manifest|Coverage|Receipt|Mapping|Argument`结尾但同时携带Core与Digest的对象就是该对象的Envelope，不构成例外。普通嵌套摘要也必须指向已命名且可取得的完整preimage：`ExactCoverageRefDigest=DIGEST(ExactCoverageRef的完整canonical bytes)`、`ProducedMemberBindingDigest=DIGEST(ProducedMemberBinding的完整canonical bytes)`、`PrepublicationTargetSlotTokenDigest=DIGEST(PrepublicationTargetSlotToken的完整canonical bytes)`、`FinalCandidateSealDigest=DIGEST(Base exact final Candidate Seal完整canonical bytes)`、`FinalPublishedInferenceStateDigest=DIGEST(exact final Published Inference State完整canonical bytes)`；不得用显示ID或未定义的`DIGEST(object)`代替。

真实Knowledge Gate与Publication使用以下唯一隔离边界：`ExactKnowledgeStateExecutionBoundaryCore=TUPLE(ENUM(KNOWLEDGE_STATE_EXECUTION_BOUNDARY_CORE),PRODUCTION(ExactProductionAuthorityStoreRef,ExactProductionCurrentNamespaceRef)|CAPABILITY_VALIDATION(ExactCapabilityValidationRunRef,ExactValidationOnlyAuthorityStoreRef,ExactValidationOnlyCurrentNamespaceRef))`；`ExactKnowledgeStateExecutionBoundaryDigest=DIGEST(ExactKnowledgeStateExecutionBoundaryCore)`；`ExactKnowledgeStateExecutionBoundaryRef=TUPLE(ENUM(KNOWLEDGE_STATE_EXECUTION_BOUNDARY_REF),ExactKnowledgeStateExecutionBoundaryCore,ExactKnowledgeStateExecutionBoundaryDigest)`。四种exact Ref均由Application Authority正式状态解析：production store/namespace只能标记`PRODUCTION`并指向production authority store及其production CURRENT namespace；validation run/store/namespace必须共同标记同一个exact `CAPABILITY_VALIDATION` run、`VALIDATION_ONLY` authority store及该run专属validation CURRENT namespace。两种variant的store identity、namespace identity、root/state index、CURRENT keyspace和可见性域必须不相等、不可别名且不可切换。这里不注册`CAPABILITY_EVALUATION` Candidate、Admission或Publication variant；该Purpose只能进入Pack的隔离Evaluation Sink，不能构造本Ref或进入本Schema真实Knowledge Gate。

每一轮Candidate Bundle的固定时序为：Application Authority已按该轮可用basis签发Manifest（COVERAGE basis须先满足此前正式化规则） → `BeginCandidateBundle`只冻结Candidate Envelope、Authority Input Manifest与Verification Seed → 本轮获授权的Source/Observation或正式Snapshot读取 → Artifact/Evidence或正式Premise → `ProposalPublicArgument → InterpretedSemanticResult` → 按Execution Class形成执行证明分支（MODEL_REVIEWED：Generation/Review Proposal及PRODUCTION/CAPABILITY_EVALUATION的Eligibility/Eligible Binding，或CAPABILITY_VALIDATION的两个Fixture Binding；MECHANICAL：`MechanicalRuleExecutionManifest`） → 独立`RuleVerificationDecision` → `CanonicalRuleOutput` → `CandidatePrebinding → SelfCandidateToken → EnumerationProofCoverage → PostRuleEnumerationBindingProof → StructuredArgument` → 聚合全部Final State Candidate并依次冻结`Revision002SubstitutionInvariantClosureCore → Digest → Local Reference Substitution Manifest → final Candidate Seal` → Knowledge Verifier独立重算并形成Admission Decision → Snapshot Builder逐字形成Target Local Identity、分配`PrepublicationTargetSlotToken`并从已准入Candidate Coverage/Produced Binding生成、随Candidate Publication Manifest冻结`ProducedBindingReceiptRequirementSet` → Application Acceptance → Publication Request → Publisher创建Publication Attempt → Receipt/Manifest/Mapping与Snapshot/CURRENT原子发布。没有Inference或枚举的分支跳过不适用节点，但不得改变剩余节点相对顺序。任何阶段不得提前生成后续对象；当前轮新形成的Coverage只能成为后续新Attempt/Manifest/Envelope的basis。

最终Publication事务必须在Application Acceptance与Publication Request之后，由Publisher创建真实Publication Attempt；它先从不可变Admission历史用`ExactAdmissionDecisionRef + finalCandidateSeal + CandidatePrebindingCore`重建SelfCandidateToken，并逐字重建CandidateRootLocalIdentity、TargetLocalRef、Admission绑定的Local Reference Substitution Manifest及`Revision002SubstitutionInvariantClosureCore/Digest`，再在would-be published State中重验kind/type、Role Registry链、Extraction Rule、FieldPath、raw digest、Projection Rule和projected digest。随后为`ProducedBindingReceiptRequirementSet`中的每项Requirement原子生成恰好一个Receipt，并仅按Manifest唯一Entry形成一一对应Mapping；局部引用替换前后按完整Candidate集合、全部member ordinal、Context/Argument/Coverage/Rule/Premise/Capability Provenance、Hard Atomic Edge、Publication Prerequisite和所有local-ref位置递归重算的Substitution-Invariant Closure Digest必须不变。LINK必须复用Root/knowledgeId但写目标Snapshot的新State/新Formal Ref；CREATE_NEW必须在提交点重验无同Key Root并只分配一个。final Published Inference State必须引用完整`ProducedBindingReceiptClosureRef`与`FinalProvenanceDependencyManifest`，后者通过该Closure逐项闭合全部Receipt Ref；最终Publication Receipt与Snapshot Provenance Manifest必须保存全部Mapping。Receipt、final Manifest、final State、Mapping与Snapshot/CURRENT切换全部生效或全部不生效。Coverage保留原Candidate Binding及digest，但脱离对应Receipt、final Manifest与Mapping时不得再被承认为COMPLETE。

Receipt、Admission历史、final State、`FinalProvenanceDependencyManifest`、final Publication Receipt及Snapshot Provenance Manifest按Snapshot同等append-only保留，不得物理清理或原地替换。历史Snapshot Reader/Verifier必须由Published State取得final Manifest及Receipt closure，按唯一索引解析恰好一项Receipt及Mapping，回读mapping中的目标Snapshot exact FormalRef，再从Admission历史与该Snapshot完整State集合分别独立重建`Revision002SubstitutionInvariantClosureCore/Digest`，并按Local Reference Substitution Manifest、Role Registry、Extraction Catalog与FieldPath重算身份替换、raw与projected term。LINK Mapping的final Ref若仍是授权来源的旧Snapshot Ref、Root/knowledgeId不同或未形成新State，CREATE_NEW存在同Key Root或分配多个Root，以及Entry/Root/State Mapping非一一对应，都必须失败；零项、多项、删除/篡改Receipt、只剩SelfCandidateToken、Admission seal不一致、错Snapshot/slot/Formal Ref或后续Snapshot沿用旧Mapping同样失败关闭。跨Snapshot Continuation只允许一个机械路径：以旧Published State的Resolved Formal Knowledge Ref作为新Application Attempt中Candidate的正式Premise，形成新的Candidate Envelope、CandidatePrebindingCore、SelfCandidateToken及适用的post-rule Proof/StructuredArgument，聚合完整Final State Candidate后依次形成`Revision002SubstitutionInvariantClosureCore/Digest → Local Reference Substitution Manifest → final Candidate Seal → Verification/Admission Decision → Prepublication Slot → Receipt/Final Manifest/Mapping`，再经完整Publication时序发布。旧SelfCandidateToken、Coverage、Receipt、Manifest或Mapping保持append-only且不得复用或原地修改；“旧Token配新Snapshot”、无新Admission的重铸、或把该路径冒充unchanged continuation均失败关闭。

任一缺失或不一致中止整个Admission/Publication，不允许先发布再补Receipt，也不制造Candidate premise循环。

`analysis-domain.exclusions`与Completeness使用以下封闭矩阵；其中RequestedBasis指消费该domain的enumeration-proof basis，若domain尚未被消费则以自身semantic-boundary与domainKind作为同等检查边界。`COVERAGE_PARTIAL`无条件强制PARTIAL；`DYNAMIC_BINDING_UNRESOLVED|EXTERNAL_API_SEMANTICS_UNKNOWN|CONFIGURATION_UNRESOLVED|CONTEXT_NOT_COMPARABLE|MODEL_REVIEW_DISAGREEMENT|NUMERIC_POLICY_UNRESOLVED|ORDERING_UNRESOLVED`存在即强制PARTIAL。`SOURCE_BOUNDARY_ONLY`只在RequestedBasis明确限定同一source boundary且不要求runtime语义时兼容COMPLETE；`RUNTIME_STATE_UNOBSERVED`只在RequestedBasis明确要求declared-source semantics且排除runtime时兼容COMPLETE；`COMPONENT_VERSION_NOT_INDEPENDENTLY_RESOLVED`只在exact Framework fallback且requested不要求独立component version时兼容COMPLETE；`COMPARATOR_ORDER_NOT_EQUIVALENT`只在requested要求exact comparator行为而非数值全序时兼容COMPLETE。任一limitation的affected term属于projected requested且不满足上述兼容条件时强制PARTIAL。

所有无序集合以member canonical digest升序保存；PATH与语义步骤保持声明顺序。Coverage内Reference必须可解析、同Boundary/Scope/Schema/Context；跨BEFORE/AFTER只允许Comparison Role显式声明。Candidate-local Ref只允许作为enumeration-proof `ProducedMemberBinding.CANDIDATE_UNDER_REVIEW`直接项，且只能引用当前受审Candidate；它不能嵌入CoverageTerm、RequestedBasis、ExactCoverageRef或ProposalCoverageRef。SelfCandidateToken只绑定不含Binding/Coverage/Result/RuleOutput/CapabilityProvenance/StructuredArgument的CandidatePrebinding Core/Digest；Verifier必须取得完整Prebinding Envelope并从当前冻结候选重建，不能由Producer任选。动态CURRENT、其他Candidate Ref、Coverage自引用、Artifact Payload、Evidence Quote、任意map/text、Answer Claim、模型摘要及未注册Value Object在任意递归深度均非法。Coverage Digest只覆盖对应Coverage Core；不能忽略unknown field、把Envelope当preimage或在Core内放自身Digest后重算。

Coverage本身不能支持用户软件Claim；集合语义必须由`closed-set-observation` Fact或相应Inference Conclusion表达。

## 7. Fact Type Extension

### 7.1 共通规则

Base Fact 共通规则全部有效。本文新增的 Fact：

- 至少有一个 Entity Term。
- Canonical Proposition 中的所有表达式、位置、call、query和constraint必须使用 §5 Value Object。
- Observation Modality 是命题组成部分。
- 每个语义路径被 exact Provider Observation 与 content-span / complete-set Evidence直接覆盖。
- Rule Pack输出只进入本文注册的typed Inference Argument；Direct Fact必须由Evidence与Direct Support Contract建立，不能借用MECHANICAL Rule Output替代。API、框架、跨节点、mapper/query效果、外部组件或模型审核的解释同样必须形成Inference。
- 空 closed set 是正向“exact selector结果为空”命题，不是全局否定 Fact。

### 7.3 Role 与支持约束

1. `build-declaration` 的九个 Role 互不等价；`MANAGES_DEPENDENCY` 与`DECLARES_PARENT`不能作为直接依赖边；`DECLARES_PARENT`保存parent component/version declaration；`DECLARES_PROPERTY|DECLARES_PROFILE|DECLARES_ACTIVATION|DECLARES_CONFIGURATION`只证明source typed key/value/predicate。`BUILD-EFFECTIVE-VALUE@1`最多在Argument内机械规范化单个scalar声明表达式，不能生成effective dependency。只有`BUILD-EFFECTIVE-DEPENDENCY-RESOLUTION@1`在target module、完整effective descriptor chain、候选/冲突/mediation closure和独立审核全部闭合后，才能支持带exact version的`RESOLVES_EFFECTIVE_DEPENDENCY`。
2. Program Fact 只陈述源码结构。条件、公式、argument、lvalue/rvalue、字段和值不能降级为自然语言。
3. `program-state-effect` 不能指向query operation或外部API effect。源码中的operation invocation只形成 `program-call` Fact；mapper binding与query declaration分别形成自己的Fact，调用造成的数据流、SQL effect或外部API effect只能在后续Inference组合，Fact不按方法名猜测。
4. Query/schema Entity 可以由 mention锚定，但每个 predicate、field、constraint、mapper binding仍需自己的直接 Evidence。
5. `closed-set-observation` 的 member exact allowlist 只有：Typed Literal；`swm.value.source-node-ref@1`、`swm.value.type-ref@1`、`swm.value.location-ref@1`、`swm.value.expression@1`、`swm.value.call-binding@1`、`swm.value.query-expression@1`、`swm.value.constraint-definition@1`；以及 Kind 为 `swm.entity.source-unit@1 | swm.entity.software-module@1 | swm.entity.code-symbol@1 | swm.entity.git-revision@1 | swm.entity.dependency-component@1 | swm.entity.structured-source-symbol@1` 且由同一 Support Closure 直接锚定的 Entity Reference。`swm.value.closed-selector@1`、`swm.value.semantic-delta@1`、`swm.value.guarantee-claim@1`、`swm.value.valuation@1` 和所有未列类型都不能成为 member。对每个允许 member 的完整递归value/term子树执行约束：任何 Fact 或 Inference Formal Reference 出现在任意深度都非法；Entity Reference也只能满足本条同一Support Closure与Kind allowlist。memberType必须由selector固定且全体同型。
6. Build descriptor固定为`source-unit`、owner固定为`software-module`，declarationRole→target只有以下映射：`AGGREGATES_MODULE→software-module`；`IDENTIFIES_COMPONENT|MANAGES_DEPENDENCY|DECLARES_DEPENDENCY|DECLARES_PARENT→dependency-component`；`DECLARES_PROPERTY→NativeKey(PROPERTY)`；`DECLARES_PROFILE→NativeKey(PROFILE)`；`DECLARES_ACTIVATION→NativeKey(ACTIVATION)`；`DECLARES_CONFIGURATION→NativeKey(CONFIGURATION)`。role-target错配非法，不能使用`software-module|dependency-component`宽联合；component与module的后续绑定只能由`BUILD-COMPONENT-MODULE-BINDING@1`形成derived relation。program owner/annotation target/mapper operation=`code-symbol`；query/relation/field/constraint=`structured-source-symbol`；closed-set anchor=`source-unit|software-module|code-symbol|git-revision|structured-source-symbol`。
7. `MAPPER_BINDING_TWO_REGION@1` 只允许一个完整 mapping declaration Evidence 明示 namespace/operation binding，另一个完整 declaration Evidence锚定 exact mapper code-symbol；二者必须同Repository/exact Commit，且 namespace、operation ID和signature机械唯一。任一关系需要名称相似、运行配置或模型关联时不得构造Fact。该Fact只陈述声明绑定，不蕴含调用已执行或产生INSERT/UPDATE等效果。

### 8.3 分轮构建

`INITIAL` 仍不能发布 Inference。典型顺序是：

1. INITIAL 或 UNCHANGED 发布来源锚定 Entity 与直接 Fact。
2. 新 UNCHANGED Attempt 发布 derived-relation / external-api-semantic / expression-semantics。
3. 再次 UNCHANGED 发布 graph-analysis / declared-program-behavior / semantic-change。
4. 需要上游 Inference 的 guarantee-assessment / counterexample在后续 UNCHANGED Attempt 发布。

增加轮次不降低可表达性；任何实现不得把同一轮 Candidate 当作前提来缩短流程。
