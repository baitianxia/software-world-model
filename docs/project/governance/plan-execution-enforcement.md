# 开发计划执行规则

## 目的

计划执行的首要目标是持续完成用户可验证的产品结果，并尽早发现方向偏差。机械检查只保护真实权限、安全和完成真实性，不能把计划、收据
或验证器变成主要交付物，也不能让普通开发失败自动停止整个开发回合。

## 执行的最简原则

执行控制只保留能直接防止目标偏离的最小动作：一个当前任务、一个用户结果、一个监督判断和一个下一动作。不得为了证明执行受控而新增
状态机、摘要层、逐失败门禁、重复收据或并行审批；已有 Git、测试、运行证据和监督子 Agent 足够时直接复用。任何新增控制都必须先说明
它阻止的具体偏离，以及为什么现有手段不能阻止；否则不加入开发流程。

## 持续授权与工作计划必须分离

仓库必须区分两个对象：

- **持续授权边界（standing authority）：** 唯一的权限来源，规定允许的代码范围、Source、只读/写入、外部接收方、配置路线、披露、
  预算、loopback/Production 和撤销条件。
- **工作计划（work plan）：** 当前产品目标、任务顺序、最早可验证纵切、已知阻塞和下一开发任务。实现者可依据新证据在既有授权内直接
  调整；它不能创建、扩大、撤销、消费或暂停授权。

Manifest 的 current action 是工作计划与审计定位的兼容镜像，不是新的人工授权来源。coding_allowed、external_execution_allowed、
路径和 lock 字段必须镜像持续授权与真实安全边界，不能因答案错误、测试失败、格式失败、检查点未达成、Result 缺失或计划文字更新而把仍
有效的开发授权改成 false。

只有真实 scope delta 才申请最小增量权限：私有或来源不明数据、新的外部接收方或账户、扩大披露/预算、外部写入、非 loopback、
Production 或破坏性动作。同一公开开源 exact revision、既有路线、预算和只读范围内的新问题、Conversation、Turn、候选、定向测试与本地
启动不重复申请。

## 一个持续的产品开发闭环

下面的箭头只表示开发活动的反馈方向，不是产品运行时的组件流水线。产品运行时应保持 Agent 主导的可往返闭环。

活动 Slice 默认只有一个持续产品开发闭环：

    理解目标 → 形成最小纵切 → 定向验证 → 立即交付真实 Web
        ↑             ↓
        └─ 分层归因 ← 普通失败/用户反馈

普通失败留在同一 Slice：保存原输入、输出和证据，定位 Source truth、世界模型认知、Agent 规划/工具使用、Evidence/Answer、Review 或 Web
呈现中的最早偏差，做通用修复并用不同类型、未参与修复的问题复验。上述项目是诊断责任层，不是规定运行时先后顺序。不得为单题、提交、测试、模型调用或失败单独创建动作、PDR、Result、授权
请求或停止点；不得用题面、关键词、工程名、符号或 fixture 特判碰答案。

运行时模型不是单向链路：问题和对话上下文进入 Agent 循环；世界模型与精确版本、只读源码是两个并列的证据路径，Agent 可根据当前证据状态
选择其中之一、交替使用或在证据不足时继续调查。答案综合实际证据并生成 Citation 后交给独立 Reviewer；Reviewer 发现缺口时把具体反馈送回
同一个 Agent 循环，而不是重新生成一份互相比较的答案；通过后由 Chat 承载和呈现本轮结果。

第一个贯通世界模型认知、主工程 Agent、按 Gap 只读源码、Evidence/Citation、fresh Review 和语义多轮 Chat 的浏览器版本一旦可操作，
必须立即交给用户。首次交付 requires_result=false，不移动计划游标，也不等待全量回归、跨工程、hidden、完整比较基础设施或工程夯实。
用户可以随时 REWORK / REDIRECT / STOP / REJECT；听取这类反馈不要求产品先取得技术 PASS。

方向确认前只运行改动相关的 targeted、startup、安全和失败真实性验证。实际体验后再用异质问题和 current Codex 强基线判断方向；Codex
不是事实来源、Oracle 或裁判。方向成立后才执行全面夯实和完整回归。

## 任务拆分完整性约束

计划在执行前必须通过结构检查，不能只靠文字提醒开发 Agent：

1. 当前 Slice 只能有一份 `current` 执行计划、一个 `current_task` 和一条顺序；Phase、C/N 编号、能力包或历史 PDR 不能在当前计划中形成第二套前置链。
2. 第一任务必须同时包含最小真实世界模型、Agent、源码补证、答案、Citation、独立复核和可持续浏览器；配置、监督、全量测试、Codex 比较和工程夯实不得成为其前置任务。
3. 每个任务必须具备用户结果、最小证据、允许的内部工作、失败出口和下一动作；缺少其中任一项不得标记为当前任务。
4. 任务计划不得绑定过期 commit、旧 run 或旧监督 HEAD。精确版本只在候选冻结和运行收据中绑定；普通提交不自动使任务失效，也不要求重建整套前置证据。
5. `project/current.md`、活动 Manifest 和当前执行计划的 Slice、任务、顺序和出口必须一致；不一致时只阻止计划变更或完成声明，不撤销仍有效的开发授权。
6. 计划形状检查只验证结构和边界，不判断答案质量、不发起模型调用、不修改架构、不替代独立复核；计划通过不等于产品通过。

计划修订只允许在当前 Slice 内直接收敛，除非发生 scope/Owner 变化、用户明确转向或安全禁止。普通失败不能生成新的 PDR、Result、授权请求
或产品阶段；失败必须回到当前任务的最早责任层。

## 最小机械边界

机械检查只应拒绝当前具体 diff、外部操作或完成声明中的以下错误：

1. 候选超出可信持续授权的路径、Source、披露、预算、写入、网络、loopback/Production 或破坏性边界；
2. 候选计划试图为自己的同一 diff 创建或扩大权限；
3. 外部副作用缺少既有 standing authority 或必要的自动运行记录，Secret 被写入仓库、Prompt、日志或 Result；
4. 未发生的产品体验、测试、答案、Citation、Review、比较或完成状态被宣称为已发生。

检查失败只阻止该 diff、操作或完成声明；修正后继续原开发闭环。它不得撤销未越界的开发权限、生成失败 Result、移动全局游标，或要求用户
重新批准同一范围。Git commit/tree 已提供版本绑定；运行记录用于审计真实外调，不应复制为整套计划状态机。

## Result 与计划修订

Result 用于最终完成/方向交接或确实需要迁移项目状态时密封已发生事实，不是过程日志。第一次 Web 交付、普通失败、定向测试、内部候选和
同范围 REWORK 都不需要 Result。若已有历史 Result 记录失败，它保留为证据，但不撤销仍有效的 standing authority。

既有范围内，实施者可以直接修订工作计划并继续开发，无需再次取得用户授权。只有 scope delta、用户明确改变产品方向、Production/外部
边界改变或不可绕过的安全禁止才需要新的决定。计划工具表达不了真实状态时，先以当前产品目标继续所有不受影响的工作；不得建设
Activation 时钟、逐失败动作、whole-Manifest digest、冻结验证器恢复状态机或“修复门禁的门禁”。

## 时间盒、停止规则与偏航信号（2026-10-14 新增）

以下规则用于防止“持续修补但没有用户可见结果”，它们只触发交付或复审，不撤销授权：

1. **时间盒。** 当前执行计划中的每个任务都写明日历截止日期。到期时立即向用户交付最后一个可运行版本、唯一最早阻塞层和可证伪根因，
   由用户决定继续、转向或停止；不得以继续内部修复推迟交付。
2. **同签名停止。** 同一失败签名在一次通用修复后仍复现时，停止针对该签名的外部重跑，登记一条策略复审 Finding（更换实现策略或责任层），
   并在下一次交付时向用户说明。
3. **无进展上限。** 连续 10 个修复类提交没有产生新的用户可见结果时，停止提交并向用户报告当前状态与备选策略。
4. **监督如实。** 监督未实际运行（无可观察 heartbeat）时，计划不得把监督作为纠偏依据；改由每个交付出口的用户检查点替代。
5. **投入可见。** 每个交付出口附带本阶段按目录统计的代码、文档、门禁脚本与测试增量，作为偏航信号供用户判断；它不是门禁。
6. **门禁不承载迭代状态。** 通用检查脚本只检查文档结构、引用、依赖和边界；迭代专用的动作、阶段和路线状态不得写死在检查脚本中。
7. **仓库卫生。** 开发与监督克隆不得放在被 Git 忽略的运行产物目录；配置异地远程后，各活动分支至少每日推送一次。

## 验证

- python3 scripts/docs.py check：检查当前文档引用和一致性；
- python3 scripts/plan_gate.py snapshot 与 diff --base：检查当前动作结构、路径范围、门禁文件的 governance 限制和明显密钥；完成真实性由用户检查点与独立复核负责，不由脚本推断；
- python3 .git/hooks/plan-shape-check.py：检查当前计划只有一条用户价值纵切顺序、第一任务包含完整主链，且未绑定过期候选；
- 首次体验前仅运行与当前纵切相关的测试；完整回归在方向确认后的夯实阶段和最终验收前运行。

本地 hook 和远端工作流是误操作防护，不证明管理员不可绕过。不得用门禁通过数、文档数、测试数或收据数代替产品可体验性和答案质量。
