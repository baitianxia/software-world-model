## Current scoring and handoff rules

- 第一次完整主链可操作就以“开发体验候选”交付，但必须明确“质量待验证，不是 MVP”；该交付无 Result、不移动游标，且开发不停。
- 只有同一候选通过 `V-DIRECTION-QUALITY-001` 的绝对质量检查和 current Codex 同题比较，才能称为 MVP 并进入用户判向；候选变化后必须
  重新取得质量证据。
- current Codex 保留真实客户端、model、reasoning、tools 与权限，只作强基线；任何模型答案都不是真值、Oracle、Reviewer 或裁判。
- Slice1 方向 PASS 要求重大错误为 0、逐题无物质退步、总体严格超过 Codex，并有非 locator 世界模型贡献。成本、时延或调用次数不能补偿质量。
- 普通失败先作跨层归因，形成可证伪根因并做最小通用修复，再验证原失败与至少两个异质案例；同类故障复现只停止无新证据外调，产品
  开发继续。
- `FINDING-010-161` 与 PDR-011 保留历史失败；PDR-012 已恢复产品和 standing scope 内 Provider 工作，不得伪造 Answer/Citation/Review/
  Codex 比较。
- 当前 standing scope 内人工重复授权请求为 0；每个真实 dispatch 仍须 one-use exact receipt。真实 scope delta 失败关闭并单独申请。
- 用户方向只决定产品方向，不重复授权同一 standing scope；真实 scope delta 才申请增量权限。最终 Acceptance 仍需用户明确决定。
